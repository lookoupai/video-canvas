# 参考剧集导入与校订

本文记录 v0.7.2 已有接口，核对于 2026-11-21。Agent 自动语义分析、证据素材和草稿接口属于[下一阶段设计](prd-Agent驱动仿拍-2026-11-21.md)，实施后须在本页同步标注新增版本。

短剧首页点「从参考剧集创建」，进入项目后按集上传原片或选择已有视频。已有短剧也可从工作台右上角「参考剧集」进入。每集先导入拆片包或运行本地分析，点击原镜和对白可回放对应的原片区间。

「全剧角色」保存跨集的原剧身份。例如第一集的「阿澄」和第二集的「蓝衣人」可在各集下拉框中关联到同一个全剧角色。全剧角色再对应项目「角色与场景」中的新角色，形象和音色由原有角色资产管理。拆分身份时新增一个全剧角色，再改相应人物的关联。说话人不确定时保留「待确认」。

每次保存校订、导入或成功分析都产生新的修订。历史修订可回看。单集失败保留已有稿，其他集的已保存校订不受影响。保存校订后可「采用到片场」，跟拍按原镜建立片段，原创改编通过现有写稿、审核、资产拆解和分镜流程制作。

## 拆片包

导入上限为 8 MB，支持以下数据。

- `capsule_cinema.remake_reference.v1` JSON，包含 `shots[].shot/start/end/seen/camera_text` 和可选 `captions[].start/end/text/speaker`。时间以秒表示，服务器转换为毫秒。
- 包含 `VIDEO.md` 的 ZIP，可包含单层目录前缀。读取 `video/timeline.md` 或分卷 `video/timeline/*.md` 的 `videomd-timeline` 区块。存在 `video/shots/*.md` 时使用其 YAML `time` 的精确值。优先读 VTT，其次 SRT。VTT 的 `<v 人名>` 转成待关联的本集人物。
- 以下标准 JSON。它可以完整保留场次、人物和独立对白，一句对白可跨越多个镜头。

```json
{
  "scenes": [{ "id": "door", "title": "门口" }],
  "characters": [{ "id": "a", "name": "阿澄" }, { "id": "b", "name": "小舟" }],
  "shots": [
    { "id": "1", "scene_id": "door", "start_ms": 0, "end_ms": 2500, "action": "递出钥匙", "camera": "固定", "characters": ["a", "b"] },
    { "id": "2", "scene_id": "door", "start_ms": 2500, "end_ms": 5000, "action": "接过钥匙", "camera": "固定", "characters": ["b"] }
  ],
  "dialogues": [
    { "id": "d1", "start_ms": 1000, "end_ms": 3500, "text": "钥匙交给你", "speaker": "a" },
    { "id": "d2", "start_ms": 3600, "end_ms": 4500, "text": "好", "speaker": "b" }
  ]
}
```

时间使用原片本地的左闭右开毫秒区间，须落在素材实测时长内。镜号、人物 ID 和场次 ID 在同一份文档中唯一。外部包中的本机路径和网络地址作为数据忽略，播放来源始终是用户关联的素材。ZIP 只读取有限大小的文本，绝对路径、路径逃逸和符号链接会被拒绝。

## 本地分析器

上传包的导入使用 Go 内置解析器。「分析本集」由后端后台任务调用 rea-video。生产与开发 Dockerfile 都在构建时安装 Python 3.12、固定版本的 rea-video / videomd 和 FFmpeg，启动容器后直接可用，不需要进入容器安装。只有直接运行 Go 程序、不使用本仓库 Dockerfile 时，才需要自行准备 PATH 中的分析命令；未安装时仍可导入并校订。

rea-video 固定在 `538eb3a757db94826cb90c4297279e50c5dd0f83`，videomd 固定在 `083722191572ec00710c6eb69a9351809ed443ce`，依赖版本及下载哈希保存在 [reference-runtime](../../backend/reference-runtime/)。镜像使用 Debian 的 FFmpeg，支持所需的 `-fps_mode`。镜像内安装目录为 `/opt/rea-video`，保留上游 LICENSE / NOTICE；YuNet 检测模型和 MIT 许可在构建时一并下载、校验并放入 `/opt/rea-video/models`。首次构建需要下载依赖，日常启动和当前离线切镜不需要访问模型服务或下载模型权重。[rea-video](https://github.com/JuneYaooo/rea-video) · [videomd](https://github.com/videomd/videomd)

源码开发部署在仓库根目录执行 `docker compose -f docker-compose.dev.yml up -d --build`。生产部署使用从当前 fork 构建的新镜像；上游或旧版本镜像不会自动获得本次改动，见[生产部署](../docker-production.md#原片自动分析)。更新后可只读检查 `docker compose exec backend rea-video --help`，这不是安装命令。

分析命令固定使用本地模式，关闭 VLM、整片语义分析、ASR、说话人识别、音轨分离、OCR 和包装层分析。它生成切点和基于本地特征的运镜参考，动作描述、人物与对白需从已有包导入或人工补齐。这里的 `ready` 表示本次拆片成功，不代表完整理解了视频。每次尝试运行于独立临时目录，10 分钟超时，在 Unix 上取消会终止分析器及其子进程组。

当前处理结束后只导入文本元数据，抽帧等临时媒体随目录清理。下一阶段的 Agent 看图需要新增可持久读取的逐镜证据任务，不能直接复用已经清理的临时文件。现有画布 Agent 的看视频／截帧工具仍需与参考集业务归属、修订和草稿接通。[当前分析器](../../backend/internal/reference/analyzer.go) · [下一阶段实施](Agent仿拍实施与验收.md)

## 接口

以下路径均位于 `/api/v1` 登录路由下。短剧、参考集和全剧角色 ID 使用项目现有的十六进制编码。

| 操作 | 请求 |
| --- | --- |
| 新建参考项目 | `POST /drama-reference-projects`，`{title, ratio?, request_key}`，返回项目及画布 ID |
| 读取参考资料 | `GET /dramas/:id/references`，返回集序修订、各集状态、全剧角色和新角色候选 |
| 添加原片 | `POST /dramas/:id/references`，`{asset_id, title?, request_key}` |
| 重排集序 | `PUT /dramas/:id/references/order`，`{revision, ids}`，包含全部参考集 ID |
| 当前或历史稿 | `GET /dramas/:id/references/:reference?revision=`，省略修订时返回当前稿 |
| 保存校订 | `PATCH /dramas/:id/references/:reference`，`{revision, document?, bindings?, title?}`，bindings 为本集人物 ID 到全剧角色 ID 的映射 |
| 导入包 | `POST /dramas/:id/references/:reference/import`，multipart 字段 `package` 和 `revision` |
| 分析原片 | `POST /dramas/:id/references/:reference/analyze`，`{revision}` |
| 建立分析草稿 | `POST /dramas/:id/references/:reference/drafts`，`{request_key, reference_revision, instruction?, document?, prompts?, evidence?, observations?, coverage?}`，返回 201 |
| 草稿列表 | `GET /dramas/:id/references/:reference/drafts?cursor=&limit=20`，返回 `{items,next_cursor}`；limit 为 1–100，空 next_cursor 表示结束 |
| 读取／保存草稿 | `GET/PATCH /dramas/:id/references/:reference/drafts/:draft`，PATCH 必须带 `revision`，数组字段完整替换 |
| 单镜报价 | `POST /dramas/:id/references/:reference/drafts/:draft/quote`，请求 `{revision,model_id,units,max_credits?}`；只读校验并返回各镜输入、费用、资源摘要和 `plan_digest` |
| 采用分析草稿 | `POST /dramas/:id/references/:reference/drafts/:draft/apply`，请求 `{revision,request_key,plan_digest,mode:"follow",quote,target_episode_no?,episode_revision?}`；原子创建跟拍采用和所选片段并返回 `application_id` |
| 按采用计划生成 | `POST /dramas/:id/references/:reference/drafts/:draft/generate`，请求 `{revision,request_key,application_id,plan_digest,quote}`；返回批次状态、逐镜片段和可查询的任务 ID |
| 创建全剧身份 | `POST /dramas/:id/reference-roles`，`{name, target_node_id?}` |
| 改全剧身份 | `PATCH /dramas/:id/reference-roles/:role`，`{revision, name, target_node_id?}` |
| 采用到分集 | `POST /dramas/:id/references/:reference/adopt`，`{revision, request_key, mode: "follow" 或 "rewrite", instruction?, target_episode_no?, episode_revision?, shot_ids?}` |
| 已采用记录 | `GET /dramas/:id/reference-adoptions`，返回固定参考修订、实际分集 ID、当前集号与 `deleted` |

导入和分析返回 202，状态依次为 `queued` 和 `ready` 或 `failed`，按参考集独立处理。编辑与重排携带各自所见的修订，冲突返回 409。目标角色节点须属于当前短剧的画布。失败重试使用当前修订重新提交本集；新分析成功后仍保留以前的校订修订。

分析草稿独立保存，不会直接改变正式参考稿、角色绑定、分集或片段。创建时固定 `reference_revision`，缺省 `document` 复制当前参考稿；暂无分析结果时可创建空草稿再补充完整文档。同一 `request_key` 和同一输入重复提交返回原草稿，不同输入拒绝复用该键。PATCH 按草稿 `revision` 检查并发，旧版本返回 409；草稿刷新后仍可继续编辑。

草稿 `coverage` 分别记录 `shots`、`visual`、`dialogue`、`speakers`，状态为 `not_analyzed | partial | complete | unavailable`。已有镜头可以标记边界完成，但旧参考集的 `ready` 不代表视觉、对白或身份完成。`prompts` 为 `{shot_id,prompt}`；每个镜号只允许一条提示词。`evidence` 为 `{id,shot_id,asset_id,at_ms}`，必须引用本人图片并处于该镜 `[start_ms,end_ms)`；`observations` 为 `{shot_id,field,source,review_state,evidence_ids}`，字段为 `action | camera | characters | prompt`，分类为 `observation | imported | manual`，核对状态为 `observed | inferred | unknown | confirmed`，其中 `observed` 必须关联同镜帧图。外部声明的帧图时间和观察分类不等于系统提帧证明，可信媒体来源由下面的持久准备记录单独核验。

公开创建来源固定为 `external`，公开编辑记为 `manual`；请求不可设置 `source`、Agent 会话、运行 ID、状态或修改基准修订。草稿 HTTP 请求最多 2 MiB，要求最多 4000 字、单镜提示词最多 40000 字；未知 JSON 字段被拒绝。完整请求和响应类型见 [草稿数据契约](../../backend/internal/model/drama_reference_draft.go)。开发分支同时提供用户 API、短剧 Agent 工具、工作台入口和创作 CLI，尚未发布。

采用前须确认每个原人物的新角色对应与每句对白的说话人。首次采用整集；跟拍创建已锁定且可直接生成的分集，原创改编创建待写稿的未锁定分集并保存改编要求。同一提交键和相同输入返回原采用，误用于不同输入返回参数错误；相同参考修订与方式的重复点击也复用原分集。新键不会覆盖该修订先前采用的改编要求。

已有跟拍集只可由同一参考集更新，须提供当前分集修订与非空 `shot_ids`，按原镜稳定 ID 对应片段。未选择的镜头和其他分集不改，选择的视频保留，新增原镜追加，不自动删除旧镜。项目有活动任务或目标集正在生成时禁止更新。原稿、角色映射和写稿任务分别固定快照；之后校订不会改变已采用的依据或已入队的写稿输入。


## 持久媒体准备 API（A2，开发分支）

`POST /api/v1/dramas/:id/references/:reference/preparations` 接收 `{request_key,reference_revision,shot_ids?}`。同键同输入重传返回原任务；同键改变输入返回 400。同一冻结修订、原素材、实际选镜和处理版本复用同一准备，创建记录和 River 任务在同一数据库事务提交。最多 200 镜，不会静默截断。已有切镜文档直接冻结；缺文档时后台运行既有本地分析器，所得文档只保存在准备里，正式参考稿不变。

准备摘要包含 `id,reference_id,base_revision,source_asset_id,duration_ms,processor_version,status,attempt,shot_count,total_frames,completed_frames,has_audio,audio_status,error`。状态为 `queued | running | succeeded | failed | canceled`。`has_audio:null` 表示尚未探测，明确无音轨时为 `false` 且 `audio_status:unavailable`；存在音轨为 `true` 且 `audio_status:not_analyzed`。本波不做语音或说话人识别。

`GET /.../preparations`、`GET /.../preparations/:preparation` 可刷新读取列表与状态。`GET /.../:preparation/shots` 返回冻结选镜；`GET /.../:preparation/frames?shot_id=` 返回系统帧。三种列表均接收 `cursor` 与 `limit`（默认 20，最大 100），返回 `{items,next_cursor}`。准备列表按 ID 倒序，帧按生成计划 ID 正序，镜头按固定文档顺序。帧视图包含 `id,preparation_id,source_asset_id,shot_id,start_ms,end_ms,at_ms,processor_version,status,asset`；`asset` 是既有素材视图，不返回图片二进制。尚未处理为 `pending`，有效帧为 `ready`，图片被删除或损坏为 `missing`。

默认每镜采样起点、中点和终点前 100ms，时长不超过 200ms 的镜头只取中点，所有采样都在 `[start_ms,end_ms)` 内。每张 PNG 保存成功后才更新进度；系统图片使用随机持久令牌的素材地址。媒体缓存按用户、原素材、镜窗、时间点和处理版本复用，参考修订保持各自记录。复用前验证真实图片仍可读取和解码，存储服务故障作为错误处理。

`POST /.../:preparation/cancel` 立即保存取消状态，工作进程轮询后取消在途媒体命令，保留完成帧。`POST /.../:preparation/resume` 接收 `{request_key}`，检查失效帧后只对未完成项排队。进程重启由 River 恢复原尝试，已有帧跳过。`POST /.../:preparation/frames` 接收 `{request_key,frames:[{shot_id,at_ms}]}`，要求准备已停止；只能添加冻结选镜内的点，每次最多 24 点、每镜总共最多 24 点。重复点复用；单次请求重复点拒绝。恢复和补帧指令均持久记录请求键及输入指纹，不能因重传增加任务。

草稿创建允许 `preparation_id`，绑定后使用该准备的基准与完整文档初始化，即使正式参考稿已继续修改也可保留旧准备依据。证据可增加 `preparation_frame_id`；服务要求系统帧属于该准备，素材、镜号、原镜时间窗和时间点全部匹配，且真实图片仍有效。仅提交普通 `asset_id + at_ms` 仍是外部声明，不能冒充系统提帧来源。准备关联在创建后固定；后续编辑继续核验系统依据。

## 生成计划与报价

开发分支新增只读接口 `POST /dramas/:id/references/:reference/drafts/:draft/quote`。请求必须提供当前草稿 `revision`、发布中的 `model_id` 和 1–200 个单镜 `units`。每项提供 `shot_id`、`mode`（`auto | text | keyframe | image | video`）、`image_asset_ids`、申请 `duration`（秒）、`trim_start_ms`、`target_duration_ms` 和可选的模型 `params`。素材 ID 兼容素材 API 的无损 uint64 JSON 数字或十进制字符串，不能经 float64 换算。`max_credits` 是本次视频生成积分上限。草稿修订或普通参考基准过期时返回 409；不存在、越权的项目、参考集或草稿返回 404。

响应包含项目／参考／草稿 ID 与修订、模型配置摘要、`plan_digest`、总体 `executable`、总积分报价、逐镜实际规范化 `input`、素材 ID 和技术指纹、原镜 `[source_start_ms, source_end_ms)`、申请时长、输出裁剪起点／时长、单镜费用和问题列表。`blocking` 问题会令 `executable=false`。报价会读取当前发布模型快照，以生成任务相同的参数校验、参考素材检查及积分算法计算结果，但不会创建生成任务或冻结积分。素材所有权、内容对象、模型能力、参考修订和草稿修订都会在服务端复核；模型参数被规范化器丢弃或把模式参数改为冲突值时不能执行。素材 ID、内容指纹、模型快照、业务资源和输入都进入摘要，审批重验可发现草稿或素材内容变化。

`mode=auto` 按本次明确提供的参考素材与模型能力选择路线。Agnes Video 2.5 的 Flash 插件不允许视频引用，只能 720P，图片上限为 5 张；普通版本允许单条 2–12 秒视频引用、8 张图片，且输出分辨率只能是 720P／1080P／1K／2K。协议另要求输入视频小于 50 MB 且帧率 24–60 FPS，图片单张小于 15 MB、边长 256–5760 px、请求图片合计小于 50 MB；报价对视频裁片的最终大小与帧率返回复核问题，任务提交阶段须对实际裁片再次校验。`image_asset_ids` 必须指向已有的本人图片素材；目标路线如需新生关键帧，当前报价不包括该图片生成任务和对应积分。音轨是否存在不会自动转成对白证据。

Agent 采用和视频生成分别要求用户签名审批。服务重新编译原报价并要求 `plan_digest` 一致；草稿、素材、模型配置或积分变化使新提交冲突。采用在同一参考事务中写入采用记录、片段、所用提示词和裁剪范围、草稿状态及固定回执。同一请求键同一输入返回原回执，改变输入后拒绝复用。

批量生成要求该草稿的 `application_id`、报价请求、修订和摘要一致。提交前校验每个采用片段的参考集、镜号、原镜区间、修订、提示词、时长、素材和裁剪窗口。视频路线设置 `use_reference_video=true`，由片段服务根据已采用的原镜窗口生成静音裁片并替换原素材引用。Agnes 协议在冻结积分前检查实际裁片大小不超过 50 MB、时长为 2–12 秒、帧率为 24–60 FPS。生成批次和逐镜请求键先持久化，任务 ID 写入回执；重传返回现有任务，部分失败重试沿用原键。下游内部错误不会被透传为单镜错误。

短剧 Agent 使用 `drama_reference_read(scope=quote)` 获取计划，`drama_reference_apply` 与 `drama_generate_segments` 采用现有签名审批／durable 恢复。关键帧图片沿用 `generate_media` 工具及独立积分审批。确定性服务测试和隔离 HTTP CLI 测试通过；真实视觉、付费生成和最终视频质量仍待渠道验收。
