# video-canvas 短视频仿拍二开准备

**当前进度**　正式设计和交接资料已归入 fork 的 `docs/仿拍二开/`。后续开发从[项目交接](README.md)进入，产品和技术方案见[营销与短剧仿拍设计](营销与短剧仿拍设计.md)。下文记录选型时的调研依据。

调研于 2026-11-18。产品目标包括营销短视频仿拍和短剧仿拍。建议 fork `zaylora/video-canvas`，调研基线为 `master` 的 `f0b8ced`（v0.6.18）。第一条商品片可验证换商品、单镜重做和合成，再用两段连续剧情验证角色、说话人和跨场衔接。两类题材共用带时间码的分镜，分别进入营销工作室和短剧工作室。[主项目基线](https://github.com/zaylora/video-canvas/tree/f0b8ced3687b22de6af0358c682c5e768001ff4f) · [原始需求](初步需求.md)

## 短剧仿拍也纳入后，平台怎么选

对照版本为连镜 `f0b8ced` 和融光 `a43d717`，两者仓库均采用 MIT 许可。以下基于源码和工作流核对，生成质量、费用和跨集一致性尚未做同素材实测。[连镜许可](https://github.com/zaylora/video-canvas/blob/f0b8ced/LICENSE) · [融光许可](https://github.com/Stonewuu/ai-fusion-video/blob/a43d717/LICENSE)

| 我们要实现的工作 | 连镜 video-canvas | 融光 ai-fusion-video |
| --- | --- | --- |
| 从广告参考片换商品 | 营销工作室已有参考片拆镜、商品事实卡和跟拍脚本，参考视频上限 15 秒。 | 助手可接收模型支持的视频附件，所查版本中未发现同等的商品事实卡、原片时间线校验和跟拍改写流程。 |
| 从剧本拍短剧 | 支持分集规划、角色和音色资产、分镜片段多次生成、选用版本和整集合成。编写本集时可带入上一集结尾及已登记角色。 | 按集、场、镜头组织剧本与资产，镜头独立保存首尾帧及对应提示词，可选单镜生成。整集合成时会指出具体哪个镜头缺视频，可选配乐。 |
| 从已有多集成片仿拍 | 需要新增带原集号、时间码、角色身份和对白归属的拆解导入，把审核过的结果映射到短剧项目。营销参考片的 15 秒限制只适用于营销入口。 | 内置「剧本转分镜」读取已解析的剧本和场次。从视频还原这些信息、校正跨集人物，再写入该工作流，也需要开发。 |

源码依据见[连镜营销拆解](https://github.com/zaylora/video-canvas/blob/f0b8ced/backend/internal/marketing/reverse.go)、[连镜分集上下文](https://github.com/zaylora/video-canvas/blob/f0b8ced/backend/internal/drama/prompts/scripts_draft.md)、[连镜片段采用](https://github.com/zaylora/video-canvas/blob/f0b8ced/backend/internal/service/drama_segment_edit.go)、[融光剧本转分镜](https://github.com/Stonewuu/ai-fusion-video/blob/a43d717/ai-fusion-video/src/main/resources/prompts/agents/script-to-storyboard.system.md)、[融光分镜条目](https://github.com/Stonewuu/ai-fusion-video/blob/a43d717/ai-fusion-video/src/main/java/com/stonewu/fusion/entity/storyboard/StoryboardItem.java)和[融光分集合成](https://github.com/Stonewuu/ai-fusion-video/blob/a43d717/ai-fusion-video/src/main/java/com/stonewu/fusion/service/storyboard/VideoComposeService.java)。

**选择连镜做主仓。** 两边都要补参考剧集的拆解与导入，连镜已经覆盖商品跟拍，并有可承接短剧的片场。融光最值得借鉴的是按镜编辑首尾帧、保留各自修改过的提示词，以及合成前定位缺镜。若日后主营多人短剧制片、重度使用自建 ComfyUI 工作流，融光提供的项目协作和工作流导入、校验、试跑、发布会成为重新选型的理由。[融光首尾帧用例](https://github.com/Stonewuu/ai-fusion-video/blob/a43d717/ai-fusion-video-web/scripts/storyboard-frame-context.test.mjs) · [融光工作流](https://github.com/Stonewuu/ai-fusion-video/blob/a43d717/README.md#comfyui-工作流)

**短剧样片建议。** 选相邻两集各一场，同一角色跨集出现，至少有一段双人对白。导入后能点任一镜回看原片，能修正角色或说话人，并把同一角色映射到同一份新角色资产。改动其中一镜后，能保留其他已采用片段并重新合成。若采用此前调研的 `rea-toon` 做多集拆解，其 PolyForm Noncommercial 许可要求商业使用取得单独授权；也可基于 `rea-video` 的单集拆解结果自行实现跨集归并。[rea-toon 许可](https://github.com/JuneYaooo/rea-toon/blob/115d4ed/LICENSE)

`video-canvas` 的营销模块已经借鉴过 `daihuo-fanpai` 的拆解字段和跟拍方法。这次选它的理由是生成前的分段规划。首版要让用户能单独重做指定镜头时，该镜应独立提交；若为了适配模型而合并了多个镜头，界面应显示一次重做会影响哪几镜。[营销模块来源说明](https://github.com/zaylora/video-canvas/blob/f0b8ced3687b22de6af0358c682c5e768001ff4f/backend/internal/marketing/methods/NOTICE.md)

## 离线验证

| 输入 | 实际运行结果 |
| --- | --- |
| `videomd` 的 `salted-egg` 公开拆片包 | 读取 66.542 秒、21 镜、20 个切点，导出 21 份目标时长。按每段最多两镜分成 11 段，原镜号 1–21 顺序完整。这个长样例只用于验证导入器，营销工作室的参考片上限仍是 15 秒。[样例](https://github.com/videomd/videomd/tree/083722191572ec00710c6eb69a9351809ed443ce/examples/salted-egg) |
| `video-canvas` 自带的护手霜拆解 JSON | 4 镜共 10 秒，设每段最多两镜，输出镜头 1、2 对应 0–5 秒，镜头 3、4 对应 5–10 秒。[样例](https://github.com/zaylora/video-canvas/blob/f0b8ced3687b22de6af0358c682c5e768001ff4f/backend/internal/marketing/samples/cream_reverse.json) |
| 原片分镜表与自身对照，再清空对照副本的切点 | 自身对照为 `pass`，移除切点后 `cut_alignment` 检查失败，结果为 `review_required`。这是分镜数据测试。角色外观、动作连贯性、口型和实际费用仍需真实模型出片验证。 |

如需在服务器复现第一项，可在资料目录外准备一次性 Python 环境。下列命令从仓库的 `docs/仿拍二开/` 目录执行，所有下载和输出都在临时目录。

```bash
trial_dir=$(mktemp -d)
git clone -q https://github.com/videomd/videomd.git "$trial_dir/videomd"
git -C "$trial_dir/videomd" checkout -q 083722191572ec00710c6eb69a9351809ed443ce
python3 -m venv "$trial_dir/venv"
"$trial_dir/venv/bin/python" -m pip install "$trial_dir/videomd"
reader=参考源码/capsule-cinema/scripts/remake_reference.py
sample="$trial_dir/videomd/examples/salted-egg"
"$trial_dir/venv/bin/python" "$reader" sheet "$sample" -o "$trial_dir/sheet.json"
"$trial_dir/venv/bin/python" "$reader" fragments "$sample" --only targets -o "$trial_dir/targets.json"
PYTHONPATH=参考源码/daihuo-fanpai "$trial_dir/venv/bin/python" - "$trial_dir/sheet.json" <<'PY'
import json
import sys
from group_shots import group_shots

with open(sys.argv[1], encoding="utf-8") as source:
    shots = json.load(source)["shots"]
groups = group_shots(shots, max_cuts=2)
print([[shot["shot"] for shot in group] for group in groups])
PY
```

## Fork 后的第一项改动

上游营销工作室已支持整条跟拍出片，也能把脚本送到画布生成每镜一个待生成节点。现在每个节点接收同一份完整参考视频。首项改动建议从营销脚本启动逐镜任务，把**原镜时间范围、裁好的参考片段、每镜采用的生成版本**对应起来。上线前可用上游的 10 秒护手霜样例验收。[营销出片](https://github.com/zaylora/video-canvas/blob/f0b8ced3687b22de6af0358c682c5e768001ff4f/backend/internal/service/marketing_render.go) · [分镜节点构造](https://github.com/zaylora/video-canvas/blob/f0b8ced3687b22de6af0358c682c5e768001ff4f/backend/internal/agent/canvasgraph/marketing.go)

1. **生成。** 先沿用内置拆解结果，把每镜起止时间带到生成任务。若模型只能出比目标更长的片段，保留生成原件，并在合成前按用户选定的时间范围裁出目标长度。外部 `VIDEO.md` 导入可以随后接同一套分镜数据。
2. **重做。** 在四镜样片中只重做第 3 镜，验证只有这一镜产生新任务和对应费用，其他三镜继续引用原素材。用户刷新后仍可选择旧版或新版。
3. **合成。** 用提交时选定的素材 ID 和顺序生成成片。已有 `videoframe.Compose` 会统一画幅、帧率、音轨并按序拼接；短剧服务已有固定所选版本、取消和结果入库的处理。营销模块需接自己的任务入口，并在镜头缺失时让用户看到缺哪一镜。用样例核对镜序、总时长和声音接点。[合成器](https://github.com/zaylora/video-canvas/blob/f0b8ced3687b22de6af0358c682c5e768001ff4f/backend/internal/pkg/videoframe/compose.go) · [短剧合成任务](https://github.com/zaylora/video-canvas/blob/f0b8ced3687b22de6af0358c682c5e768001ff4f/backend/internal/service/drama_compose.go)

新服务器克隆 `lookoupai/video-canvas` 后即可在 `docs/仿拍二开/` 找到设计和参考源码。克隆后的 `origin` 指向自己的 fork，需要同步上游时可添加 `https://github.com/zaylora/video-canvas.git` 为 `upstream`。开发环境可用上游的 `./scripts/start-docker.sh -d` 从当前检出的源码启动，再检查 `http://localhost:8080/health`。实测出片前需配置可读参考视频或抽帧的分析模型，以及支持本次图片和视频参考的生成模型。这次验证范围为离线分镜处理，服务器部署和模型调用留到 fork 后进行。[上游开发指南](https://github.com/zaylora/video-canvas/blob/f0b8ced3687b22de6af0358c682c5e768001ff4f/docs/development.md)
