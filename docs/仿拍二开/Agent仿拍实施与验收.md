更新日期为 2026-11-21。对应[Agent 驱动仿拍方案](prd-Agent驱动仿拍-2026-11-21.md)，代码基线为 `v0.7.2` / `81522f52`。

## 2. 工程改动清单

| 范围 | 实施要求 |
| --- | --- |
| 后端模型与迁移 | 新对象加入模型注册和结构一致性测试；迁移使用当前最大编号之后的新文件，已发布迁移保持原样 |
| 后端业务 | 依赖经 initialize 注入，事务外处理媒体／模型请求，事务内完成修订校验与采用回执 |
| Agent 工具 | 同步工具 registry、schema、允许模式、视觉要求、平台工具路由、审批 kind、durable 工具恢复分类和契约测试 |
| 运行恢复 | Agent 记录准备／草稿／批准项 ID，Go 返回可重查的业务结果；新 tool call ID 不能导致重复业务写入 |
| 模型与计费 | 分析／图片／视频分别报价和记账，实际执行复核能力与素材，渠道额度失败终止对应阶段 |
| 前端 | 复用 AgentPanel、当前任务库和 gateway；直接采用与手动编辑进入同一业务服务，用户修订可见 |
| 外部客户端 | 创作 CLI 仅封装用户 API，提供 JSON、修订、请求键、任务等待及凭据私有存储，业务规则由服务端统一执行 |
| 技能接入 | 按需读方法和参考文档，记录来源、提交及许可；脚本依赖通过已登记工具提供 |
| 发布 | 新入口按功能开关逐步启用，验证旧项目、旧会话、迁移、备份与恢复；同步 CHANGELOG 和当前状态 |

| 编号 | 场景 | 通过条件 | 验证层 |
| --- | --- | --- | --- |

| T02 | 正常上传十秒四镜原片 | 四镜区间、逐镜帧时间及原片回放一致，准备任务可重复查询 | 真实媒体／集成 |
| T03 | 视觉理解动作 | 每镜动作与画面证据能对照，未知内容被标记，生成提示词在网页直接可编辑 | 模型替身结构测试＋真实视觉模型 |
| T04 | 无音轨／未接音频能力 | 两种状态分别展示，不产生假对白和说话人 | 单元／真实素材 |

| T06 | 模型支持视频参考 | 只发送选镜区间，静音、时长、素材大小和其他引用合法 | 真实媒体／真实渠道 |

| T08 | 重复准备、草稿保存、采用 | 相同业务键与输入只产生一次效果，输入改变后旧键被拒绝 | PostgreSQL 并发／HTTP |
| T09 | 生成响应丢失与 Agent 重启 | 从批准项和生成意图恢复同一任务，积分冻结一次，已生成版本保留 | 故障注入／集成 |
| T10 | 上游响应未知 | 展示待核对状态，恢复过程不会盲目新建第二个付费请求 | worker／集成 |
| T11 | 用户与 Agent 同时编辑 | 旧修订不能覆盖人工字段，差异可读取，采用失败无部分写入 | PostgreSQL／页面 |
| T12 | 只重做第三镜 | 第一、二、四镜的提示词和已采用版本保留，合成使用选定第三镜 | 真实 HTTP／FFmpeg |
| T13 | 改模型、费用或素材 | 已批准输入不会被换掉，重新规划展示变化，超预算不能执行 | 服务／审批／页面 |
| T14 | 额度不足、取消、部分失败 | 草稿与已完成证据保留，失败原因可读，只恢复相应阶段 | 服务／页面 |
| T15 | 越权与失效素材 | 其他用户或其他项目 ID、删除素材、失效证据无法被采用和计费 | 服务／handler |
| T16 | 长提示词、短窗口、刷新 | 可滚动、可聚焦、状态不遮挡输入，项目和选镜范围恢复正确 | 组件／浏览器人工核对 |
| T17 | 双集角色与对白 | 人物候选、说话人和声音证据可核对，一集修订不覆盖另一集 | B2 真实模型／集成 |
| T18 | 外部分析后站内接续 | 外部草稿和证据进入同一项目，站内 Agent 能读取，网页可直接修改并采用 | CLI／HTTP／页面 |
| T19 | 网页修改后外部继续生成 | CLI 读取最新修订和报价，旧修订冲突，平台任务和成片在网页可见 | CLI／真实生成／集成 |
| T20 | CLI 凭据和网络中断 | 普通输出无令牌，过期凭据明确退出，重试复用业务键，任务等待有超时与可恢复 ID | CLI／HTTP 故障注入 |

采用事务的冲突与并发测试使用独立测试数据库。真实生成涉及费用时使用用户明确授权的样片范围和预算。截图、视频、输入全文与运行导出存放在 `.traces/`，仓库文档保留脱敏结果。

## 4. 验证命令与记录格式

功能实现按实际改动执行以下检查。先跑相关文件／用例，再跑对应端的完整检查，涉及后台并发再跑竞态检查。

```bash
bash scripts/check.sh backend agent web
(cd agent && npm run typecheck && npm test && npm run build)
(cd backend && go test -race ./internal/tests/service/... ./internal/tests/repository/... ./internal/tests/provider/queue/...)
```

上述是实施阶段命令，尚未针对本方案运行。只涉及文档的本次交付检查 Markdown 本地链接、状态与源码一致性、差异空白和仓库范围检查。无法执行的环境依赖须注明原因及替代证据。

每次验证追加以下记录，避免把计划勾选当成证据。

| 字段 | 填写内容 |
| --- | --- |
| 日期／提交／版本 | 精确到实际被验证的代码 |
| 任务与场景 | 对应 A1–C1 和 T01–T20 |
| 环境 | 本地／独立集成环境／已部署站点 |
| 模型与能力 | 分析模型、生成模型、参考方式，渠道名称可脱敏 |
| 执行结果 | 已通过、失败、跳过、阻塞，并写原因 |
| 费用与时间 | 站内积分、能取得的渠道实扣、开始与结束时间，未知值明确写未知 |
| 画面核对 | 商品／人物、动作、构图、节奏、声音和裁剪是否达到本次目标 |
| 证据与剩余项 | 测试日志／私有运行记录路径，仍未验证的范围 |

## 5. 设计基线记录

2026-11-21 核对 v0.7.2 源码和部署记录。已有切镜、校订、采用、单镜任务、选版和合成服务可复用；独立 Agent、视觉工具、技能库及审批已存在。参考集语义草稿、业务工具、自动生成路线和工作台助手入口尚未接通。上一轮 5,149 项前端测试及发布质量检查验证的是 v0.7.2，不能计作本方案的实现验收。

此前真实原镜视频生成请求遇到渠道额度不足，尚无本方案的真实出片质量与耗时数据。首期优先完成 A1–A3 的“上传后得到有证据的可编辑分镜与提示词”，再接 A4–A7 的生成与合成闭环。

2026-11-21 用户补充站内／外部 Agent 自由选择的要求。方案增加 A8、B3 和 T18–T20，明确现有用户 API 可供脚本调用，创作 CLI 仍待实现。外部客户端通过用户 API 与网页共用草稿和制作记录，内部平台服务令牌继续只用于站内服务。
