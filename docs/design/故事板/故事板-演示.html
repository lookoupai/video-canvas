故事板演示

给每个片段先画一张宫格分镜图，生视频时让模型照着拍

现在的分镜只有文字。模型生视频时只拿到提示词和角色、场景图，不知道每个镜头该怎么构图，同一段重抽几次画面差异很大。 这次在顶部加一个「故事板」工序：每个片段按镜头数生成一张宫格图，用户先看图、定稿，到片场生视频时自动作为第 1 张参考图带上。 没有或过期的故事板只提醒，不拦截生视频。

阅读说明。项目现状来自代码（stages.ts、segment-input.ts、storyboard_draft.md）；竞品信息来自 2026-11-19 的检索。原型里的宫格图是 CSS 画的示意，生成过程用 setTimeout 模拟，功能尚未实现。完整依据见 故事板.md。
核实度图例： 已核对代码 / 官方页面 调研检索，未逐条复核 未验证 · 需实测 提案

主线：故事板插在哪、怎么被用到

顶部工序从 5 个变成 6 个，故事板夹在资产和片场之间，因为它同时需要分镜原稿和资产图。

剧本 / 拆解写剧本，拆出角色、场景、道具
资产管理生成资产图（主图）
分镜（文字）每段原稿带【时间轴】，一镜一行 已有
故事板 · 新按镜头数出宫格图，资产主图作参考，多版挑一张采用 提案
片场生视频采用的宫格图作为第 1 张参考图，加一行说明 提案
设计：故事板是片段的附属产物，从原稿推导，不反过来改原稿。现有的「分镜」按钮仍然在片场里（分镜和片段强绑定），故事板标签只负责看图和出图，不搬动分镜入口。
没有故事板时（回退，永远可用）：片场生视频的行为和今天完全一样，只在生成按钮旁多一条「未引用故事板」提醒。 模型只收首帧（i2v）或只能文生视频（t2v）时，不带宫格图，以免把宫格图当成视频首帧。

宫格怎么分：按镜头数自动

一镜一格，格子顺序就是时间轴顺序，模型和人都能对上号。镜头数从原稿【时间轴】里的「0-3秒：」这类行数出来。

1–4 镜 → 2×2
最常见

用不满的格子留白。识别不到时间轴时也按 4 格出，并提示「没识别到时间轴」。

5–6 镜 → 2×3 / 3×2
方向跟画幅

竖屏 9:16 用 2 列 3 行，横屏用 3 列 2 行，让每一格接近成片比例。

7–9 镜 → 3×3
≥10 镜会合并

超过 9 镜时，第 9 格合并剩余镜头，并提示「镜头过多，建议拆段」。

用户改了片段原稿，会发生什么

这是最容易让人困惑的地方：图已经出了，原稿又改了。

  1. 在片场改原稿并保存片段的 revision 加 1，原稿的哈希变化
  2. 采用版宫格图的 source_hash 对不上了故事板卡片显示黄角标「原稿已改」，片场芯片显示「已过期」
  3. 此时生视频照样带旧图，生成按钮旁提示「故事板已过期」
  4. 点「重新生成」新一版成功后自动采用，状态恢复正常；旧版仍保留在版本列表里
边界：不会自动重新生成。
  • 自动重跑会悄悄扣积分，所以只提醒，不自动重跑。
  • 只改错别字也会触发「已过期」，用户可以忽略。
  • 在片场重新生成整集分镜时，旧片段连同故事板一起删除，确认框里要写明张数。

交付时要说明：宫格图对视频的提升效果是社区经验，未实测；上线前需要拿同一批片段做带图和不带图的对比。

数据与接口（已实现）

故事板是短剧画布上的图片节点，和资产在同一块画布上，但不是资产：不进资产列表、不能被片段 @。后端没有新增接口、表和错误码，只读画布来数集摘要里的故事板数。对应 故事板.md 的 §8 与 §13。

故事板节点

普通的 kind: "image" 节点，data.drama 没有 type，靠 drama.board 标记属于哪个片段。

{
  "kind": "image",
  "label": "故事板 · 第 3 集 · 01",
  "prompt": "生成一张 4 格分镜图：2 列 2 行，整图比例 16:9……",
  "params": { "prompt": "…", "aspect_ratio": "16:9" },
  "model": "<图片模型>",
  "drama": {
    "episodes": [3],
    "board": { "segmentId": "5d2a", "sourceHash": "<出图时原稿的 SHA-256>", "layout": "2x2", "shotCount": 3 }
  }
}
  • 原稿里 @ 的资产节点连线进来，生成时由节点按现有规则带参考图，提示词里的 @ 换成图片编号。
  • 生成、重新生成、历史版本都是画布节点自带的流程。重新生成时用现在的原稿重写提示词和 sourceHash，保留节点上的模型和参数。
  • 新节点放在非故事板节点的右边，每集一行、每段一列。

后端：集摘要的 done_board_count

位置做什么
drama.BoardHashes解析画布 payload，收集有图（src 非空且不是 blob:）的故事板节点：片段 ID → 出图时的哈希

已确认的决定

  1. 每个片段一张宫格分镜图，生视频时作为第一张参考图。
  2. 格数按镜头数自动；故事板固定 16:9 横版（5–6 镜 3×2）。
  3. 缺失或过期只提醒，可以继续生视频。
  4. 提示词全用内置模板，去掉「画面补充说明」和详情栏，一行三张卡片。
  5. 故事板是短剧画布上的图片节点，完全复用资产管理：不能被 @，能在画布里查看、重新生成、切换历史版本；第一版的后端故事板接口和迁移已删除。
  6. 总览保留「故事板」列，后端读画布来数。
  7. 主文档已回写：§6、§7、§8、§10、§11、§13。
